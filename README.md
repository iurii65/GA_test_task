Шаг 1 Анализ исходных данных
Первоначально был проведен анализ справочника наценок, отфильтрованы неактивные и выполнена проверка, что наценки с заполненной датой окончания отсутствуют. При анализе данных натолкнулся на возможную ошибку, очень странно что в "Категория3" содержатся наименования по типу "Масло для губ_макияж" сложилось впечатление что это ошибка, т.к. Шаг 2 Определение наценки
Далее необходимо было связать наценку из справочника со списком номенклатуры с учетом приоритета. Для данной задачи была написана функция, которая для каждой строки проходит по справочнику наценок и присваевает наценку с учетом приоритета. Одновременно проставляется группа приоритета. Проверил, что отсутствуют позиции с непритянутой наценкой, дальше определили минимальную цену конкурентов. Вычислил разницу между нашими розничными ценами и ценами конкурентов. 

Шаг 3 Сравнительный анализ цен
Далее в задании необходимо было скорректировать текущую наценку, чтобы встать в минимальную цену на рынке, для решения этой задачи есть два решения.
1. Для каждой номенклатуры присвоить собственный уровень наценки, данный подход позволит гибко придерживаться стратегии компании, но в тоже время не занижать цены по товарам которые и так ниже чем у конкурентов.
2. Наценка регулируется для группы товаров, при такой схеме возможна ситуация, что из-за товара с высокой себестоимостью придется сильно снижать маржинальность остальных товаров в этой группе. Для тестовой задачи разделим популяцию, выберем две группы для предложения внесения изменения наценки в справочник. По остальным товаром возьмем минимальную цену конкурентов и проверим, что наценка не ниже 10%.

Для начала попробовали скорректировать наценку на бренд Clarins, первоначальная наценка была 103%. Однако по некоторым позициям минимальная цена конкурентов практически равнялась нашей закупочной цене. Из-за чего не получилось подобрать наценку чтобы удовлетворить два условия (цена ниже мин цены и наценка не ниже 10%). Далее взяли группу с меньшим кол-вом водящих товаров. Бренд Clarins и Категория3 Крем для тела. При первоначальной наценке в 106% удалось найти наценку удовлетворяющую двум условиям, новая наценка 35%. Однако при таком способе регулировании мы теряем маржинальность у товаров чья цена первонально уже была ниже чем у конкурентов.

По всем остальным товарам была рассчитана индивидуальная наценка, также по 104 товаром не удалось выполнять сразу два условия. Минимально разрешенная наценка в 10% не давала минимальную цену на рынке.

**Задача №5**

Чтобы решить данную задачу я решил написать код сначала на диалекте TSQL, а потом с помощью ИИ переписать для ClickHouse. Данный скрипт рассчитывает WAU скользящим окном в неделю с шагом в 1 день. Скрипт написанный на TSQL отбирает период за который необходим такой анализ (для полноценного расчета последнего дня период формируется с +6 дней). Строится таблица со списком дней за который считаем целевой показатель. Далее с помощью BETWEEN джойним по диапазону периода и рассчитываем кол-во уникальных активностей. 

Написанный скрипт переводим на диалект ClickHouse основная разница заключается в использовании конструкции (ARRAY JOIN arrayMap(i -> activity_date + i, range(7)) AS day), т.к. ClickHouse плохо работает с джойнами по диапазону поэтому здесь применяется обратная логика. Каждая активность пользователей раздается на 7 дней вперед. Т.е. включается в показатель WAU на 7 дней вперед.
